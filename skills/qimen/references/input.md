# 输入与输出约定

## 普通对话

用户给“我想问本月底能否拿到录用通知，2026 年 9 月 13 日 10:30，北京起局”即可。模型转换内部格式，不把收集数据变成填表。

日柱需要年月日，时柱需要时分或已核验的完整时干支。默认公历；农历先核对是否闰月并转换，不能把农历数字当公历传入。用户给明确时辰而交节或换日会影响结果时，确认原时间或使用可靠原盘。问题、期限和原始角色保存在 `question` 中。

城市用于判断民用时区，未指定时区默认 Asia/Shanghai 并注明。程序不作经度、均时差或真太阳时校正；不把“北京时间”和“真太阳时”视为同一设置。

## 公历自动排盘

```json
{
  "question": "我想问本月底能否拿到录用通知。",
  "time": {
    "kind": "civil",
    "at": "2026-09-13T10:30:00",
    "timezone": "Asia/Shanghai",
    "day_boundary": "midnight"
  },
  "method": "chaibu"
}
```

- `at` 至少含时分；支持 ISO 8601 UTC 偏移。有偏移时先转换为所指定时区；无偏移时按指定时区解释。
- `midnight` 零点换日，`zi23` 23 点换日。两种约定下时干均依所选日干作五鼠遁，避免日、时柱各用一套晚子时规则。
- 程序按真实时刻转 UTC+8 查询节气；年柱在立春交接时刻换，月柱在十二节交接时刻换，定局用全部二十四节气。日、时按用户所选民用时区计算。
- 自动历法范围 1900—2100。夏令时重复／不存在的当地时间须明确 UTC 偏移后重试。
- 未说明换日习惯时不必每次询问，采用默认并记录；原盘已写明的约定优先。

## 按现在

```json
{"question":"按现在起局问本周合作能否落实。","time":{"kind":"now","timezone":"Asia/Shanghai"}}
```

仅适用用户明确要求现在起局。实际执行时刻写入输出 `calendar.at`，不可用“现在”重建一张过去的盘。

## 已有干支，按拆补计算

```json
{
  "question": "复核课堂示例盘。",
  "time": {
    "kind": "manual",
    "year_ganzhi": "壬寅",
    "month_ganzhi": "乙巳",
    "day_ganzhi": "乙酉",
    "hour_ganzhi": "辛巳",
    "solar_term": "小满",
    "source": "用户给出的四柱和节气"
  },
  "method": "chaibu"
}
```

必填 `day_ganzhi`、`hour_ganzhi`、`source`；拆补另需 `solar_term`。年、月可省略，但涉及年干、月干或旺衰的分析相应暂缺。程序检查六十甲子是否合法、日时是否符合五鼠遁，以及同时提供的月支与节气是否对应；不会反推或认证公历日期。

## 手动指定阴阳遁与局数

```json
{
  "question": "按这组定局条件复核转盘。",
  "time": {"kind":"manual","day_ganzhi":"乙酉","hour_ganzhi":"辛巳","source":"用户原盘"},
  "method": "manual",
  "dun": "yang",
  "ju": 2
}
```

`dun` 为 `yang` 或 `yin`；`ju` 为整数 1—9。`time` 也可以是公历。手动定局只表示局数来自输入，后续仍是本版转盘、五寄坤二，**不是置闰、茅山或飞盘算法的实现**。输出 `day_yuan` 在手动定局时仅为日符头标签，不声称该局按拆补推得。

拒绝未知字段和互相矛盾的模式，不允许一边写 `chaibu` 一边输入希望得到的局数。

## 已有盘／截图

直接从原盘识别九宫数据并保留来源。能用本版程序复核时，可另排一份核对；不覆盖原盘。原盘排法与程序不同则解释差异，不能为运行程序而擅自改成拆补。

优先确认影响当前主用神的模糊格子。盘面明显标注“腾蛇”可等同程序“螣蛇”；“天芮／天禽”“本干／寄干”须区分。输入程序目前不支持导入九宫数组；人工转录盘不标为“程序已校验”。

## 程序输出

- `calendar`：时间、四柱、节气、换日和来源。
- `day_futou`／`day_yuan`：日干支推符头与三元；`xun_head`／`xun_yi`：**时**旬首与遁仪，两者用途不同。
- `xun_original_palace`：旬仪原始地盘宫（可能是 5）；`zhishi_raw_palace` 为九宫飞数终点，寄宫后的结果另列。
- `zhifu_star`：值符星；五宫时为天禽，`zhifu_carrier_star` 为随转的天芮。`god="值符"` 是八神值符。
- `palaces`：数组按 1—9 宫编号，**不是显示顺序**。展示为 `4 9 2 / 3 5 7 / 8 1 6`。
- `earth_stems`／`heaven_stems`：本干在先，寄干在后。五宫保留地盘原干，二宫列其寄干；天盘寄干跟随天禽天芮转动，不在五宫再造一份天盘。
- `stem_pairs`：包含寄干的可见上下组合，附寄干标志；这是数据枚举，不能把每一对都当同等权重的独立格局。
- `stem_stages`：干对落宫内**每个地支**的天干十二长生；不含另一套五行墓。
- `hour_void`／`hour_horse`：时旬空、时支驿马；宫内 `void_branches` 精确保留哪个地支空，不擅称半空／全空的效力。
- `inner`：阳遁一八三四为内、阴遁九二七六为内；中五不强行分内外。
- `global_facts`：全盘星／门伏吟反吟、五不遇时的条件标记。
- `day_to_hour_palace_relation`：日干宫对时干宫的方向；“生”是日宫生时宫，“被克”是时宫克日宫；`opposite` 与五行生克分别列。

输出目录只用新路径。保存 `analysis.md` 时不要覆盖 `chart.md` 的机器底稿或改写 `input.json`。
