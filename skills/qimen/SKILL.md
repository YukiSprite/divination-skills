# 奇门排盘与解读

以随附程序产生可复核的盘面，依据课程规则解释用户所问之事。中文回复，先回应问题，再说明用神及关系。“按此局，我倾向……”表达传统规则下的判断，不把类象写成已证实的现实事实。

本 skill 独立于六爻、八字、塔罗；不把其他体系的取用、旺衰或起局方法混入本盘。原始转录已整理为随附 references，正常使用无需访问作者电脑的“本地参考文件”，也无需联网。

## 输入与任务选择

读取 [输入约定](references/input.md)，区分：

- **按时间起局并解读：** 保留具体问题、占问对象、现实背景与期限。询问缺失且会改变取用或排盘的信息即可，不让用户填写内部 JSON。
- **解已有盘：** 优先沿用用户原盘，核对九宫、天地盘干、星门神、值符值使、起局时间和排法。图片看不清的格子明确待确认，不以另起的新盘补上。不因默认拆补法与原盘不同就判原盘错误。
- **只排盘：** 输出程序盘面即可，不强加占断。
- **学规则／问流派：** 读取对应参考文件解释，不要求先起一局。

用户给旧时间时沿用旧时间；只有明确说“按现在起局”等才用 `time.kind=now`。未给时间时不能悄悄用分析时刻替代。日期缺时分应问清；已知明确时辰且提供了可靠干支，可以用手动输入。

默认是**转盘、拆补法、五寄坤二、天禽随天芮、天盘八神、Asia/Shanghai 民用时间、零点换日**。这些是本版工程约定，不声称各流派统一如此。用户另有明确排法则尊重；自动程序未实现置闰、茅山、飞盘、真太阳时，不用默认盘冒充其指定结果。需要比较时分别保留两套盘和约定。

## 排盘

起新局或复核本版排法时，读取 [排盘规则](references/paipan.md)，用 Python 3.9+ 调用随附程序。历法依赖已附在 `vendor`，不需要 API 密钥或临时联网安装。

1. 将输入规范化成 JSON 文件。用户文字写入文件或使用结构化参数，勿拼接进可执行命令。
2. 执行：

   ```text
   python3 -B <skill目录>/scripts/paipan.py --input <输入JSON路径>
   ```

   保存盘面时加 `--output-dir <新的输出目录>`，得到 `input.json`、`chart.json`、`chart.md`。程序拒绝覆盖已有目录。
3. 读取完整 JSON，核对时间来源、日符头与时旬首、阴阳遁与局数、寄干、值符值使、时旬空和时马。程序报错时先纠正输入或恢复依赖，不凭记忆拼盘绕过错误。
4. 原样使用 `chart_markdown` 中的九宫表，或在保留数据的前提下精简展示。盘面上南下北、左东右西；五宫原干与二宫寄干不是两份独立用神。八神“值符”与“值符星”分清。

程序产出的是关系事实，不是完成的占断。`facts`、`global_facts`、`stem_pairs` 不能直接换成吉凶判词。

## 解读

排盘后读取 [用神与分析规则](references/interpretation.md)，按“确定主用神 → 跨宫关系 → 宫内状态 → 归回问题”处理。

- 默认以日干看求测者、时干看事情，并按实际问题选最直接的专项用神。先固定人物和符号对应，再解释；不因为结论不合预想就悄悄更换用神。取用有歧义时简短说明主取法，仅讨论会改变结论的其他取法。
- 甲日、甲时、甲年命须使用**该完整干支**对应的六甲遁仪。不能见甲就一概当戊，也不能拿时旬首替所有甲。
- 跨宫比较的是**用神所落宫的五行**。宫内再分别看星、门、天地盘干和宫的关系，不将“庚金克乙木”冒充“庚落宮克乙落宫”。
- 八门和九星旺衰用不同的表；十干十二长生按阳顺阴逆、戊随丙己随丁。不要套用六爻的土水同宫。遇到四隅宫两个地支时，分支列状态，不任选一个覆盖另一个。
- 象意按 [类象索引](references/symbols.md) 使用；取与问题相关的少量象，不堆砌长相、职业、数字等未经证实的细节。
- 涉及十干克应、伏吟反吟、击刑、入墓、门迫等时，读 [格局与克应](references/patterns.md)。入墓、空亡、反吟、吉门或凶门都不是一条即可定成败的公式。
- 感情题另读 [感情取用与案例](references/relationships.md)。乙庚、日时、年命的角色要与实际关系对应；丙丁出现不代表现实中已经有第三者，空亡、死门不证明配偶死亡或离婚。
- 每个主要判断写清“哪个用神、在哪宫、与谁发生什么关系、如何联系所问”，附简短规则编号（如 R04、G03）即可。课程案例的反馈与当前用户的现实事实分开。
- 给出有力度边界的主倾向，例如偏顺、偏阻、可推进但反复；依据相反时交代主次和最关键的变数。若原盘关键字段缺失，说明能判断的部分并问清，不硬给完整盘的结论。
- 未收录的完整克应口诀、应期算法、择日择方术不凭记忆补齐。资料中的近远快慢只作相对提示，不能推出精确日期、身高、金额或成功概率。

健康、法律、财务等现实决策按实际证据处理，传统类象不作为诊断、归罪或投资承诺的依据；不复用案例中对女性、职业或第三方动机的贬损判断。普通占问不固定附长篇免责声明。

## 交付

通常先回答所问，再给起局约定、九宫盘和 2—4 条关键依据。复杂问题可增加主用神表与支持／阻碍；简单问题不用固定长模板。术语随用随解释。

用户要保存完整解读时，在新输出目录另写 `analysis.md`，保留原始输入和机器盘；不要修改盘面以贴合后来的反馈。用户只要规则讲解时，可不展示无关盘面。
